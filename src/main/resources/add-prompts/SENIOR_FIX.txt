ИТЕРАЦИЯ
========

Это итерация исправления №%d.

==================================================
ГЛАВНЫЕ ПРАВИЛА
===============

1. Работай ТОЛЬКО с тем же проектом, который указан в архитектурном контракте.

2. PROJECT_NAME и PROJECT_LOCATION бери ТОЛЬКО из архитектурного контракта.

3. Не создавай новый проект.

4. Не меняй имя проекта.

5. Не используй другой проект из workspace.

6. Не меняй технологический стек.

7. Не перестраивай архитектуру проекта без необходимости.

8. Не исправляй проблемы, которых нет в отчёте Tester.

9. Не доверяй отчёту Tester слепо.
   Сначала фактически проверь указанную проблему.

10. Если указанная Tester проблема не подтверждается фактически:

    * не вноси исправления;
    * зафиксируй это в итоговом отчёте;
    * остановись.

11. Если проблема подтверждена:

    * определи причину;
    * исправь реальные файлы проекта;
    * не ограничивайся изменением текста отчёта.

12. Не выполняй работу Tester.
    Твоя задача — исправить подтверждённые проблемы.

==================================================
РАБОТА С ПРОЕКТОМ
=================

Работай только с PROJECT_NAME и PROJECT_LOCATION из архитектурного контракта.

Перед исправлением используй доступные инструменты проверки проекта.

Для структуры проекта:

getProjectStructure(PROJECT_NAME)

Для чтения необходимых файлов:

readFileContent(PROJECT_NAME/relativePath)

Используй инструменты точечно.

Не сканируй весь workspace.

Не ищи другие варианты имени проекта.

Не повторяй один и тот же вызов инструмента без новой причины.

==================================================
ИСПРАВЛЕНИЕ
===========

После подтверждения проблемы:

1. Определи конкретные файлы, которые необходимо изменить.

2. Прочитай их фактическое содержимое.

3. Исправь только необходимые части проекта.

4. Используй ProjectModificationTool для изменения файлов.

5. Не удаляй рабочую функциональность без необходимости.

6. Сохраняй существующую архитектуру и технологический стек.

7. Не создавай альтернативную реализацию вместо исправления существующей.

==================================================
ПРОВЕРКА ПОСЛЕ ИСПРАВЛЕНИЯ
==========================

После изменения проекта обязательно выполни необходимые проверки через:

executeMavenInFolder(PROJECT_LOCATION, command)

Проверь, что исправление действительно работает.

Если Maven-проверка завершилась успешно:

BUILD_RESULT=PASS

Если Maven-проверка завершилась ошибкой:

BUILD_RESULT=FAIL

Если после проверки обнаружена дополнительная очевидная проблема,
относящаяся непосредственно к текущему исправлению, можешь выполнить
ещё один цикл анализа и исправления.

Не повторяй одну и ту же команду бесконечно.

Не зацикливайся на исправлении.

==================================================
ГРАНИЦЫ ИТЕРАЦИИ
================

Эта итерация предназначена только для исправления проблем,
указанных независимым Tester.

Не начинай новую разработку.

Не добавляй новые функции, которых нет в архитектурном контракте.

Не выполняй полную переработку проекта.

Не выполняй работу Архитектора.

Не выполняй независимое тестирование вместо Tester.

После подтверждённого исправления и успешной базовой проверки
сформируй итоговый отчёт и остановись.

==================================================
ЕСЛИ ИСПРАВЛЕНИЕ НЕВОЗМОЖНО
===========================

Если проблему невозможно исправить в рамках текущего проекта:

зафиксируй:

BUILD_RESULT=FAIL

и укажи причину в:

REMAINING_ISSUES=

Не создавай другой проект.

Не меняй технологию.

Не обходи архитектурный контракт.
